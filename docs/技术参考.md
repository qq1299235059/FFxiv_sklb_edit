# 服装骨架技术参考

## 0.5 场景角色来源

使用当前已安装、已编译验证的 FFXIVClientStructs Human.RaceSexId / Top.Id 以及 Dalamud IObjectTable / ITargetManager.Target，在 Framework 线程读取所选角色的人形模型。只支持已识别的可玩种族模型码；空目标、非人物、未加载模型或未知变体不推测回退。对应原版 `base/b0001` 资源直接从 SqPack 读取，不读取当前角色加载的 Mod skeleton 或姿态。

原版 `extra_top.est` 以装备集合和模型码查找直接上衣关联。没有条目或骨架 ID 为 0 时返回不可用；不跨种族猜测。另选服装骨架必须与所选人物模型相符。原版参考路径及哈希随项目保存，回导依据项目来源复核；人物选择信息不改变 glTF 中保护原服装骨骼的规则。

0.5 本机已验证自己模型 c0201 的 106 骨导出、空目标拒绝、Blender 返回及原生文件转换；实际目标角色正向导出和角色运动尚未验收。116 项核心检查包含模型来源、跨种族拒绝、EST 截断/重复/空关联和已有骨架往返。

## 格式选择

本版采用 glTF 2.0 加配套 JSON。glTF 的节点、局部变换、skin joints 和 extras 适合检查骨骼层级与身份，Blender 自带导入导出器可直接使用。FBX 在未加权骨骼、骨轴和附加信息往返上需要更多专门处理；当前选择以实际 Blender 往返结果为依据。

glTF 规范来自 [Khronos glTF 2.0 Specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)。本项目的姿态保真以实测的骨骼局部变换比较和回导报告确认。

## 原生转换与已有接口

- [FFXIVClientStructs](https://github.com/aers/FFXIVClientStructs)：本机安装版的 Havok 结构、序列化与资源接口，是编译和执行依据。
- [Dalamud](https://github.com/goatcorp/Dalamud)：面板、插件生命周期、Framework 调度、原始 DataManager 和 IPC。
- [Lumina](https://github.com/NotAdam/Lumina)：直接读取原版 SqPack；本机版本的 MDL 解析器不适用于本次 V6 样本，因此模型检查使用已加载 Penumbra 的读取器。
- [Penumbra API](https://github.com/Ottermandias/Penumbra.Api)：集合、临时 Mod、路径解析和清理。具体签名以本机安装版程序集和 XML 文档为准。
- [Penumbra 模型工具文档](https://github.com/xivdev/Penumbra/wiki/Model-IO)：服装 MDL 与模型交换的后续接入参考；不等于本插件已实现 MDL 写回。
- [VFXEditor 的 Blender 骨架流程](https://github.com/0ceal0t/Dalamud-VFXEditor/wiki/Using-Blender-to-Edit-Skeletons-and-Animations)：既有骨架交换工作流参考。

本机 Blender 4.5.3 的 glTF 导入器确认支持 `bone_heuristic=BLENDER`、`guess_original_bind_pose=False`，导出器支持 extras、skins 和保留未加权骨骼的设置；对应代码位于安装目录 `4.5/scripts/addons_core/io_scene_gltf2`。

## 原版样本

奥丁神铠由原版中文 Item 表确认，ID 3262，ModelMain 为 `0000000000020064`，装备集合 e0100，变体 2。原版 `chara/xls/charadb/extra_top.est` 中 `(装备集合 100, 种族 201)` 指向附加骨架 100。

样本附加骨架为 `chara/human/c0201/skeleton/top/t0100/skl_c0201t0100.sklb`，SHA256 为 `4b350acf1041604f4f17c1abbbe9dceb370dfda1368e0695a64a3bd5a5b5eb28`。包含 `n_ex_top` 与 `j_ex_top_*` 共 10 根骨骼，无 mapper、local frame 或 partition，适合首轮追加验证。

基础参考为原版 `chara/human/c0201/skeleton/base/b0001/skl_c0201b0001.sklb`。这些来源直接通过原始 SqPack 读取，不使用 Penumbra 解析后的文件。

原始游戏文件、私有样本、PMP 和本机运行产物均放在私有目录内，不随插件 ZIP 打包。公开交付目录只保留干净插件包、指南、校验摘要和哈希。

更多初期技术资料和来源记录保存在 `docs/planning/initial/sources.json`。

## Layers 与运行时路径验证

SKLB 1300 的 hpla 区域记录 Layer ID 和骨索引。追加测试链时保留 Layer 25 的原成员，并追加索引 10–13。实现采用边界检查，遇到非连续偏移、越界索引、不明确的父层或非零不透明填充会停止。格式依据为 VFXEditor 的 SklbLayers 与 SklbLayer 源码。

本次只映射 t9100 时，EST 和文件预览均通过，但角色实际仍加载原版 t0100。将实际请求的 t0100 也重定向到候选文件后，本体、GPose 和 Ktisis 均确认四个 CSW 节点。原因归结到已观察到的资源路径差异，不把未追踪的内部回退机制当作已证明结论。

## 0.3 的单挂接点（历史，已由 0.4 取代）

[FFXIVClientStructs 的 SkeletonResourceHandle](https://github.com/aers/FFXIVClientStructs/blob/main/FFXIVClientStructs/FFXIV/Client/System/Resource/Handle/SkeletonResourceHandle.cs) 标出了 SKLB 头的连接字段；[VFXEditor 的 SklbNewData](https://github.com/0ceal0t/Dalamud-VFXEditor/blob/main/VFXEditor/Formats/SklbFormat/Data/SklbNewData.cs) 提供对应的新格式读取。[PartialSkeleton](https://github.com/aers/FFXIVClientStructs/blob/main/FFXIVClientStructs/FFXIV/Client/Graphics/Render/PartialSkeleton.cs) 记录运行时的 ConnectedParentBoneIndex 和 ConnectedBoneIndex。上述源码与本机原版样本、原生重新读取共同构成依据，不能替代角色实际运动验收。

本机原版中原女奥丁模板的连接索引为 22，连接到基础骨架 j_sebo_c；原版手骨 j_te_l / j_te_r 的索引为 64 / 65，由当次读取的参考解析，代码不固定写入这些数字。0.3 将整套装备的根移到目标人体骨，不能满足独立骨链手动设父级。此前据 1300 模板推断的单连接限制不适用于 1301 多根格式，0.4 已修正。

此轮用户指定先完成开发，游戏运动验证稍后进行。已验证 Blender 左右手定位、三段链加末端节点、原生转换及重新加载、连接字段和骨骼层。仍未验证角色手腕运动、服装顶点权重、新动画或物理链。

## 0.4 的完整挂点与多根格式

依据本机原始 SqPack 样本及安装版本的 SkeletonResourceHandle / SklbNewData 结构，确认以下已识别布局，不将它推广为所有 SKLB 版本的通用规则：

| 字段或样本 | 观察结果 |
| --- | --- |
| 1301 描述区域 | 48 字节；偏移 16 为 0；偏移 40 为 4 个 Int16 基础骨索引，后续空位 -1 |
| 原版 c0201 top t0377 | 6 个节点，根为 j_ude_b_l / j_ude_b_r，连接 59 / 60，Layer 4 / 5 / 25 |
| 原版 c0201 top t0505 | 3 个连接 11 / 59 / 60，Layer 4 / 5 / 6 / 25 |
| 原版 c0201 top t0100 | 1300 单根 10 节点，偏移 16 为 22，Layer 25 |
| 原版 c0201 base b0001 | 106 个基础骨骼，j_te_l / j_te_r 为 64 / 65 |

连接对应的根必须按顺序占据骨数组前部。本实现保留原连接，在后面加入实际使用的新挂点根，再重排原非根及新增骨；hpla 内原骨索引按身份重映射。新人体根加入参考的唯一 Layer，新增服装骨进入 Layer 25。原骨 XML 静止变换原样复用，父关系按身份保持，但数组索引可能改变。含 mapper、local frame、partition 或未知引用结构的模板拒绝改写。

Blender 的完整基础骨架与服装骨骼位于同一 armature。用户对新链手动设置父级，导出临时副本仅保留直接被新增骨使用的挂点，未用挂点和辅助祖先忽略；现有装备挂接会复用原根。当前支持已核对的最多 4 个实际连接，原装备连接也计入；不代表游戏所有骨架格式只有 4 个连接。

0.4 文件试验结果为 10 原骨 + 8 新骨 + 2 手部挂点，共 20 个节点。真实 Blender 验证手动父级、导出模型空间位置、104 个挂点清理及工作场景保留；游戏进程 Havok 验证转换和重新读取，SKLB 连接为 22 / 64 / 65、骨骼层为 4 / 5 / 25。102 项核心检查通过。本机证据位于 `outputs/anchor-rig-check/report.json`。

这些检查证明本轮交换文件和原生序列化结果，不证明实际角色加载后的连接运动。外部 MDL、PAP、SKP、PHYB 没有由插件改写，索引变化对外部引用的影响、原服装行为、手腕随动与加权效果均需进游戏验证。
