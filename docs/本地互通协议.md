# 本地互通协议 1（插件 0.6）

## 连接边界

游戏侧监听 `127.0.0.1:43867`，端口可在指引中配置；Blender 使用同一端口。一次支持一个活动 Blender 客户端，10 秒无认证请求后允许其他实例连接。仅支持同机。无需 HTTP URL ACL、管理员权限或防火墙规则。

HTTP/1.1、JSON UTF-8，请求必须有 Content-Length，最大正文 48 MiB、头部 16 KiB、4 个并发请求、单次请求超时 5 秒。POST 需 `X-CSW-Protocol: 1` 和 application/json。拒绝 Origin、重复头、分块传输及非指定回环 Host；不配置 CORS。Blender 绕过系统代理，后台线程发送，主线程只消费队列。

该服务是同机编辑工具，不是对其他本机进程的安全隔离。不要改为监听局域网或公网。临时 token 不写入磁盘或日志，项目只记录非个人化人物模型和资源来源。

## 接口

| 方法和路径 | 内容 |
| --- | --- |
| GET /v1/health | 返回 protocol、version、port，不返回凭据或文件路径 |
| POST /v1/connect | `{protocol:1, clientId:UUID}` → 临时 token、instanceId；其他活动客户端返回 409 |
| POST /v1/poll | 获取尚未确认的 project、消息和返回计数 |
| POST /v1/ack | `{transferId:UUID}` 确认本次发送 |
| POST /v1/return | 返回编辑文件，先验证后保存 |
| POST /v1/disconnect | 立即释放当前连接 |

connect 以外的 POST 还需 X-CSW-Client 和 X-CSW-Token。401 时重新握手；409 表示项目、连接占用、版本或当前忙碌状态冲突；无效内容 400。Blender 会自动重连，游戏正在回导时保留待返回内容并稍后重试。其他返回错误会显示提示，用户可更正后重新点击返回。

## 项目与返回

项目 envelope：`{projectId, revision, transferId, files}`。files 为固定文件名到 Base64 字节的映射，允许 skeleton/reference 的 gltf、ffxiv.json、complete.json、可选 bin，以及 anchor-rig.json。不得发送原始 SKLB/HKX、配置、主机路径或人物身份。

revision 为按固定文件顺序逐个追加“UTF-8 文件名 + Int32 小端字节长度 + 文件内容”后的 SHA256。transferId 每次发送更新；revision 相同且当前场景已有同项目骨架时仅确认接收，保留已有编辑。重新创建项目会使用新的 projectId，导入新对象。

Blender 骨架对象保存 revision 和原项目身份；返回 envelope：`{projectId, revision, requestId, files}`，只包含 edited.gltf、edited.ffxiv.json、edited.complete.json。glTF 的二进制 buffer 内嵌，主机路径与 Blender 自定义属性在导出时清理。游戏核对项目及 revision，核心 importer 校验原骨身份、姿态、父级与完成哈希，通过后在固定插件目录事务发布，完成标记最后写入。

重复 requestId 的相同正文幂等成功；内容不同拒绝。新项目或过期 revision 的返回拒绝，不覆盖原有效文件。网络接收线程不调用游戏 API。用户在游戏点击回导后，Framework 线程使用原版资源和现有原生验证链转换 SKLB。

Blender 使用自己的本地缓存目录，短摘要目录名避免 Windows 长路径问题。缓存、.blend、返回文件和项目都不是分发内容。用户仍需自行保存工作工程。
