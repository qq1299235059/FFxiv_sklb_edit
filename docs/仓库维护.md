# GitHub 与 Dalamud 仓库维护

公开仓库为 `qq1299235059/FFxiv_sklb_edit`，默认分支 `main`。用户长期订阅同一个地址：

```text
https://raw.githubusercontent.com/qq1299235059/FFxiv_sklb_edit/main/repo.json
```

`repo.json` 是 JSON 数组，保存游戏插件的完整元数据、版本与安装/更新链接。版本文件保存在 `downloads/版本号/`，可以直接经 HTTPS GET 下载，无需登录或 GitHub Pages。Blender 工具同时包含在 Dalamud ZIP 内，另提供单独 ZIP。

## 更新步骤

1. 修改游戏插件 csproj 的 Version、插件 JSON 的 AssemblyVersion，以及 Blender 的 bl_info version，保持一致。同步首页和使用指南的版本。核对客户端和 Dalamud API；不要把未测试的新版本标为兼容。
2. 更新 README、使用指南和变更说明；功能改变后完成相关测试。保留角色运动、文件转换和 Blender 检查之间的区别。
3. 运行 `./tools/build.ps1 -Test` 与 `./tools/build.ps1 -Release`，再运行 `python tools/package_release.py`。切换版本时将旧 `outputs/delivery` 完整移到私有历史目录，保持交付目录清单干净。
4. 运行 `tools/test_release_portability.py --blender <本机程序> --source <本机原版导出项目>`，检查真正打包后的工具。测试项目、日志、配置和游戏资源不提交。
5. 运行 `python tools/prepare_repository.py`，生成版本下载目录、独立 Blender ZIP、校验摘要与 repo.json。此步骤会校验包与桥接源码一致、来源报告匹配、ZIP 内部哈希和路径脱敏；已存在的版本文件若不同会拒绝覆盖，应提升版本。
6. 审查并提交源码、文档、`repo.json` 和 `downloads/新版本/`。不要提交 `.tools`、`work`、`outputs`、`bin`、`obj`、本机设置、游戏资源、PDB 或私人样本。
7. 在提交后通过无登录 HTTP GET 读取 repo.json，下载它声明的 ZIP，核对 SHA256 和内部版本。验证通过后再通知使用者更新。

安装器依靠 AssemblyVersion 判断更新，LastUpdate 为 Unix 秒。只替换 ZIP 而不提高版本，已安装用户不会得到正常的版本更新。版本化下载文件应保持不变。

## 本地构建

`tools/bootstrap_sdk.py` 下载并校验固定的 .NET SDK。构建脚本默认从当前用户国服启动器的开发程序集目录解析引用；其他布局可以在未提交的 `config/local.props` 配置 DalamudLibPath。该配置必须只包含使用者自己的位置。

发行包只包含项目实现与配套脚本，Dalamud、FFXIVClientStructs、Lumina 与 Penumbra 由目标环境提供。游戏原版资源在使用者本机读取；下载目录不得加入 SKLB、HKX、MDL、PMP、工作项目或场景文件。

公开托管仅包含脱敏源码与干净发行文件。首次设置、Blender 程序地址和开发模式开关由安装后生成，开发文件指令默认关闭。

格式依据：[Dalamud 自定义仓库文档](https://dalamud.dev/plugin-publishing/custom-repositories/)。
