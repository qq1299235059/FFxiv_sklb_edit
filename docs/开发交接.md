# 服装骨架工作台开发交接

## 当前版本：0.4 完整人体挂点

用户要求继续使用装备附加骨架，并修正 Blender 工作方式：同一套骨架提供完整的人体挂点，用户自行设置新增骨链的父级，未使用的挂点在导出时自动忽略。0.3 的整套装备换挂点流程已停用；升级后必须新建项目并重新打开 Blender。

本轮按照用户要求完成开发与文件验证，角色动作由用户稍后进游戏验收。没有改动人物 Mod 的基础骨架，没有安装新测试 Mod，也没有向角色应用临时预览。

### Blender 编辑与返回

`anchor-rig.json` 描述原装备连接、同种族性别的原版人体参考、模型空间静止姿态与来源哈希。`anchors.py` 将参考加入服装的同一 armature；已有同名原骨保留身份与父关系，其他人体骨骼标记为挂点辅助骨，并放入专用骨骼集合。中原女原版基础骨架提供 106 个可选骨骼。

新增骨链可通过编辑模式 Ctrl+P → 保持偏移手动指定父级，也可在活动挂点上使用“添加三段骨链”。已有链改父级时只重设链的第一根。面板显示新增骨、可选挂点与使用挂点数量。

返回时创建临时骨架副本，仅保留作为新增骨父级的挂点；所用挂点改为导出根，未用挂点及其人体祖先自动忽略。若选中的是原装备已经使用的挂接点，则复用原根。原 Blender 场景保留完整挂点。导出补偿保留挂点的规范姿态与直接子骨的局部变换，保持新增骨的模型空间位置。挂点被移动、改名，原骨被修改或新链没有父级时拒绝返回，保留上一次有效文件。

### 多根 SKLB 与保真边界

本轮确认原版 1301 装备 SKLB 存在多连接布局。原版中原女 t0377 有 2 个连接根，t0505 有 3 个连接根；这推翻了 0.3 把单连接模板推广为通用限制的结论。已识别的 48 字节描述在偏移 40 存放 4 个 Int16 人体索引，未用位置为 -1；根节点必须按连接顺序放在骨数组前部。本实现最多支持该已验证布局的 4 个直接连接，原装备连接计入，多条链可复用同一连接。

`EquipmentAnchorPlan` 从原版源文件和重新读取的参考建立受哈希约束的计划。原根在前、所用新挂点随后，再排列原非根和新增骨。原骨名字、父级身份、静止姿态、W 与原连接保留；原数组索引可能移动，SKLB 内 hpla 层索引同步重映射。新挂点加入原版参考中对应的唯一 Layer，新增服装骨加入已验证的 Layer 25。只有使用新挂点时才将 1300 提升为 1301；无新挂点的普通追加保留原排列。

可信 Havok XML 来自原始二进制，只重建 skeleton 的 bones、referencePose、parentIndices。原骨的 XML pose 和 bone 元素原样复用在新位置，其他对象保留。保存后重新加载原生二进制，逐骨比较名称、父级、TRS、W、LockTranslation，再重建 SKLB 包装和层数据。

只接受已识别的简单 top 模板、已核对的根姿态与完整连接描述。已有 mapper、local frame、partition、额外 variant 或未知辅助索引结构会拒绝。外部 MDL、PAP、SKP、PHYB 不在本次重映射范围；仅凭 SKLB 结构通过不能推断这些文件兼容，也不能推断动作和物理行为正确。

### 本轮验证

在国服客户端 `2026.10.06.0000.0000`、Dalamud 15.0.3.7 / API 15、Blender 4.5.3 LTS 上完成：

- 102 项核心检查通过，覆盖多根排列、连接字段、原骨 pose 和父关系、层重映射、glTF 身份及错误输入拒绝。
- 真实 Blender 后台操作加载 10 根奥丁原骨与 106 个人体挂点；手动把两条完整链分别挂在左右手。返回为 20 节点：10 原骨、8 新骨、2 挂点，忽略其余 104 个挂点。
- 验证活动挂点添加、原挂点复用、多链共用挂点、重复导出、未用挂点修改后忽略、工作场景不被清理、失败不覆盖有效返回文件。
- 游戏进程内 Havok 完成原版双根 t0377 的原样往返，以及左右手候选的转换和重新读取。候选 1301 的连接为原胸部连接与左右手；样本实际索引为 22、64、65，代码按参考解析，不固定写入。
- 只生成 EST 测试包，并在未分配角色的临时 Penumbra 集合登记、核对和撤销。未安装、未应用到角色，`gameMotionVerified=false`。

本机证据在 `outputs/anchor-rig-check/report.json`。0.4 的抬臂、屈肘、手腕随动、原装备行为、外部动画/物理引用及服装加权仍待用户验收。后台 Blender 操作测试不等于手动点击界面验收。

## 运行目录与首次设置

所有运行目录由 `IDalamudPluginInterface.AssemblyLocation` 确定。项目位于 `Projects`，回导固定为 `BlenderReturn/edited.gltf`，桥接工具随包位于 `BlenderBridge`；设置中的项目和候选路径相对插件目录保存。Blender 地址只保存在本机，不预填开发设备地址。首次指引、空白或失效地址的设置弹窗已在此前版本的游戏界面验收。

Blender 使用独立新进程的 `--factory-startup --python` 加载工具，用户资源与临时文件在 `BlenderSession`，不保存用户偏好。GUI 启动通过 timer 等待窗口上下文，不能重新读取 factory settings 或写只读 Region.active_panel_category。返回通过同目录临时发布文件原子替换，避免临时目录权限随文件移动进入返回目录。

complete 文件绑定 glTF 哈希与节点数，sidecar 绑定项目身份。游戏每秒检查返回；其他项目文件、新修改未校验、候选哈希不匹配均阻止误用。旧整套换挂点的候选拒绝继续预览或打包。

| src/ClothingSkeleton.Plugin/RuntimeSkeletonInspection.cs | 只读检查实际资源、连接和骨名 |

| tests/ClothingSkeleton.Tests/AnchorChecks.cs | 多挂点的核心检查 |
| tools/test_native_anchor_rig.ps1 | 原版与实际游戏 Havok 文件集成检查 |
| tools/blender_anchor_rig_smoke.py | 真实 Blender 的手动父级与清理检查 |
| tools/test_release_portability.py | 实际 ZIP 的空格/中文目录迁移检查 |

本地 SDK 为 .NET 10.0.100，NuGet 源为空。`tools/build.ps1 -Test` 执行核心检查，`-Release` 构建发行文件，`-Probe` 更新环境读取工具。只引用本机 Dalamud 程序集，不复制 Dalamud、FFXIVClientStructs 或 Penumbra 实现程序集到 ZIP。

`/csw` 打开界面。开发文件指令默认关闭，只有本机设置显式启用 `EnableDevelopmentCommands` 时读取 `Development/runtime-command.json`；`tools/runtime_request.py` 提供有界请求。安装/启用测试 Mod 等可改变持久状态的专项命令仍须用户授权。

公共发行由 `tools/package_release.py` 使用文件清单生成，不带 PDB、设置、日志、工作项目或游戏资源。源码经 PathMap 处理，打包扫描 UTF-8 与两种对齐的 UTF-16 内容，禁止实际主机路径。分发仅取 `outputs/delivery` 中的干净包与指南；本机测试项目留在私有目录。

## 既有实装证据与下一步

此前中原女奥丁的 14 节点样本已经实装，用户在 Ktisis 确认看见 CSW 三段链及末端；原版 `j_ex_top_*` 属于装备本身。本轮没有覆盖该持久测试 Mod。该既有证据不能代替 0.4 多挂点候选的角色运动验收。
