# 服装骨架工作台开发交接

## 当前版本：0.6.1 骨骼集合与原骨状态检查

Blender 面板移除两种添加操作，使用原生 Shift+A / E / Shift+D。三个受管理的骨骼集合分别是“人物骨骼”“服装原骨”“服装骨骼”。首次导入或旧场景迁移时分类，原生新增骨自动分类；用户手动放错已有骨骼时不自动消除错误，由状态检查报告并阻止返回。“整理新增服装骨骼”仅整理新骨集合，不改父级、姿态、当前模式，支持 Blender 撤销。

原生挤出/复制可能继承父骨自定义属性。同步只在源骨仍存在时为新副本分配新身份并去掉继承的保护标记；原骨身份、改名、变换与父级保护仍保留。人物对照从游戏导出的 reference.ffxiv.json 与初次 glTF 导入矩阵建立，另存于骨架对象；旧 0.6 场景重发同一项目后以原始导入矩阵补充对照，不以当前编辑姿态重新建立基准。

检查区分集合归属和骨骼父级：自定义链挂在人体挂点下合法；新骨误入人物集合，或人物原骨父级、静止姿态、名字、存在性被改变，显示错误并禁止返回。人物辅助骨的轴矩阵允许 Blender 模式切换产生的微小舍入，位置保持原精度；原装备和原生回导校验精度不变。

`tools/blender_collections_smoke.py` 在真实 Blender 验证原生操作、集合分类、错误检查、一键整理和返回保护；`test_release_portability.py` 对包内及独立安装版执行同一检查，继续验证本地互通。

## 0.6 本机端口互通（历史背景）

游戏侧 `BlenderBridgeServer` 使用 TcpListener 监听 IPv4 回环地址，默认 43867；无需管理员或 HTTP URL ACL。Blender 安装并启用配套插件后连接游戏；不再查找 blender.exe，不启动进程，也不加载新的 .blend。旧地址设置只用于兼容读取和脱敏，保存时清空；设置版本升为 4，升级后显示新的连接指引。

`BridgeExchange` 只发送 glTF、身份资料、原版人物挂点信息及必要 buffer；原始 SKLB/HKX 和配置留在游戏侧。连接采用限长 JSON、协议头、进程期临时凭据、单客户端占用和短超时；禁止浏览器 Origin、系统代理和非回环 Host。完整协议见 [本地互通协议](本地互通协议.md)。

Blender 的 `connection.py` 后台线程只处理 HTTP，主线程 timer 导入场景；编辑模式或模态操作期间等待。项目内容摘要相同则复用现有骨架，不覆盖编辑；新项目新增对象。导入失败只移除此次创建的对象。返回先在本机缓存导出，数据通过端口发回；游戏先用核心 importer 校验，再事务写入固定返回文件，完成标记最后发布。请求身份支持幂等重试，原生回导期间暂停接收写入。

已通过 133 项核心检查、同一真实 Blender 进程中的多项目接收、重复发送/断线重连保留编辑、编辑模式延后导入、两份网络返回的核心校验。真实分发包在空格和中文目录，以及 Blender 自身安装独立 ZIP 后均通过相同流程。游戏内实际服务也完成左右手骨链接收与返回；角色动作、服装权重和外部动画/物理仍待用户验收。无新角色预览或持久 Mod 安装。

以下为 0.5 和更早版本的实现背景；旧版启动 Blender 的步骤以 0.6 文档为准。

## 0.5 场景角色骨架来源（历史背景）

用户明确选择从场景中的“自己 / 当前目标”导出对应的原版人物骨架，不使用人物 Mod 附带骨架。新增 `CharacterSkeletonReader` 在 Framework 线程确认所选对象为已加载 Human 模型，读取 RaceSexId 与上衣集合；随后仅通过原始 DataManager/SqPack 读取原版资源，不复制实时 skeleton、动作姿态或 Mod 文件。

准备页新增“读取自己”“读取当前目标”，取消预设中原女人物参考。当前上衣可按原版 extra_top.est 的模型/装备二元键找到直接关联；缺失时显示不可用，不猜测种族回退或套用奥丁模板。用户仍可另选匹配种族性别的服装 SKLB。人物来源与服装回导目标分开，继续使用装备附加骨架路线，不写回人物基础 SKLB。

选择快照只在内存保存对象身份，导出前重新核对角色、模型和上衣；目标消失、切换或不支持时拒绝。公开或项目记录只保存来源种类、模型类型、装备集合、原版游戏路径与哈希，不保存角色姓名、账号、内容 ID、对象 ID 或指针。

`anchor-rig.json` 增加 CharacterSource；Blender 0.5 要求明确的 self/target 来源和匹配的原版参考路径。旧 0.4 项目在导入对象前拒绝，不加载预设参考，也不覆盖有效返回。游戏按钮也提前提示重新创建；设置迁移不会把旧版来源 0（奥丁样本）解释为新版来源 0（当前上衣）。回导从项目保存的人物来源重新读取原版资源并校验哈希，不按服装另选人物参考。

116 项核心检查通过；当前游戏中的自己识别为 c0201，已导出 106 根原版人物骨骼，完成真实 Blender 左右手骨链返回、20 节点原生 SKLB 转换及未分配角色的 Penumbra 登记撤销。当前目标为空时已验证拒绝，没有切回自己。没有对目标角色进行正向场景验证，没有应用新角色预览或安装新 Mod；动作、外部动画/物理和服装权重继续待验收。

开发命令增加 `select-character --selection self|target`，文件测试先明确读取角色，再 inspect。开发接口最终仍关闭。旧版项目可以保留备份，0.5 的 Blender 编辑需重新创建项目。以下为 0.4 实现背景，多挂点及保真边界继续适用。

## 0.4 完整人体挂点（历史背景）

用户要求继续使用装备附加骨架，并修正 Blender 工作方式：同一套骨架提供完整的人体挂点，用户自行设置新增骨链的父级，未使用的挂点在导出时自动忽略。0.3 的整套装备换挂点流程已停用；升级后必须新建项目并重新打开 Blender。

本轮按照用户要求完成开发与文件验证，角色动作由用户稍后进游戏验收。没有改动人物 Mod 的基础骨架，没有安装新测试 Mod，也没有向角色应用临时预览。

### Blender 编辑与返回

`anchor-rig.json` 描述原装备连接、同种族性别的原版人体参考、模型空间静止姿态与来源哈希。`anchors.py` 将参考加入服装的同一 armature；已有同名原骨保留身份与父关系，其他人体骨骼标记为挂点辅助骨，并放入专用骨骼集合。中原女原版基础骨架提供 106 个可选骨骼。

新增骨链可通过编辑模式 Ctrl+P → 保持偏移手动指定父级，也可在活动挂点上使用“添加三段骨链”。已有链改父级时只重设链的第一根。面板显示新增骨、可选挂点与使用挂点数量。

返回时创建临时骨架副本，仅保留作为新增骨父级的挂点；所用挂点改为导出根，未用挂点及其人体祖先自动忽略。若选中的是原装备已经使用的挂接点，则复用原根。原 Blender 场景保留完整挂点。导出补偿保留挂点的规范姿态与直接子骨的局部变换，保持新增骨的模型空间位置。挂点被移动、改名，原骨被修改或新链没有父级时拒绝返回，保留上一次有效文件。

### 多根 SKLB 与保真边界

本轮确认原版 1301 装备 SKLB 存在多连接布局。原版中原女 t0377 有 2 个连接根，t0505 有 3 个连接根；这推翻了 0.3 把单连接模板推广为通用限制的结论。已识别的 48 字节描述在偏移 40 存放 4 个 Int16 人体索引，未用位置为 -1；根节点必须按连接顺序放在骨数组前部。本实现最多支持该已验证布局的 4 个直接连接，原装备连接计入，多条链可复用同一连接。

`EquipmentAnchorPlan` 从原版源文件和重新读取的参考建立受哈希约束的计划。原根在前、所用新挂点随后，再排列原非根和新增骨。原骨名字、父级身份、静止姿态、W 与原连接保留；原数组索引可能移动，SKLB 内 hpla 层索引同步重映射。新挂点加入原版参考中对应的唯一 Layer，新增服装骨加入已验证的 Layer 25。只有使用新挂点时才将 1300 提升为 1301；无新挂点的普通追加保留原排列。

可信 Havok XML 来自原始二进制，只重建 skeleton 的 bones、referencePose、parentIndices。原骨的 XML pose 和 bone 元素原样复用在新位置，其他对象保留。保存后重新加载原生二进制，逐骨比较名称、父级、TRS、W、LockTranslation，再重建 SKLB 包装和层数据。

只接受已识别的简单 top 模板、已核对的根姿态与完整连接描述。已有 mapper、local frame、partition、额外 variant 或未知辅助索引结构会拒绝。外部 MDL、PAP、SKP、PHYB 不在本次重映射范围；仅凭 SKLB 结构通过不能推断这些文件兼容，也不能推断动作和物理行为正确。

### 本轮验证

在国服客户端 `2026.10.06.0000.0000`、Dalamud 15.0.3.7 / API 15、Blender 4.5.3 LTS 上完成：

- 102 项核心检查通过，覆盖多根排列、连接字段、原骨 pose 和父关系、层重映射、glTF 身份及错误输入拒绝。
- 真实 Blender 后台操作加载 10 根奥丁原骨与 106 个人体挂点；手动把两条完整链分别挂在左右手。返回为 20 节点：10 原骨、8 新骨、2 挂点，忽略其余 104 个挂点。
- 验证活动挂点添加、原挂点复用、多链共用挂点、重复导出、未用挂点修改后忽略、工作场景不被清理、失败不覆盖有效返回文件。
- 游戏进程内 Havok 完成原版双根 t0377 的原样往返，以及左右手候选的转换和重新读取。候选 1301 的连接为原胸部连接与左右手；样本实际索引为 22、64、65，代码按参考解析，不固定写入。
- 只生成 EST 测试包，并在未分配角色的临时 Penumbra 集合登记、核对和撤销。未安装、未应用到角色，`gameMotionVerified=false`。

本机证据在 `outputs/anchor-rig-check/report.json`。0.4 的抬臂、屈肘、手腕随动、原装备行为、外部动画/物理引用及服装加权仍待用户验收。后台 Blender 操作测试不等于手动点击界面验收。

## 运行目录与首次设置

所有运行目录由 `IDalamudPluginInterface.AssemblyLocation` 确定。项目位于 `Projects`，回导固定为 `BlenderReturn/edited.gltf`，桥接工具随包位于 `BlenderBridge`；设置中的项目和候选路径相对插件目录保存。Blender 地址只保存在本机，不预填开发设备地址。首次指引、空白或失效地址的设置弹窗已在此前版本的游戏界面验收。

Blender 使用独立新进程的 `--factory-startup --python` 加载工具，用户资源与临时文件在 `BlenderSession`，不保存用户偏好。GUI 启动通过 timer 等待窗口上下文，不能重新读取 factory settings 或写只读 Region.active_panel_category。返回通过同目录临时发布文件原子替换，避免临时目录权限随文件移动进入返回目录。

complete 文件绑定 glTF 哈希与节点数，sidecar 绑定项目身份。游戏每秒检查返回；其他项目文件、新修改未校验、候选哈希不匹配均阻止误用。旧整套换挂点的候选拒绝继续预览或打包。
