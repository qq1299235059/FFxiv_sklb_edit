# FFXIV 服装骨骼插件开发路线

开发按可验证闭环推进。最先确认当前国服能完成未编辑往返和单骨服装蒙皮，之后再制作完整面板与 Blender 快捷操作。阶段产物以真实样例、候选文件和报告为依据。

## M0 锁定国服开发环境与首个服装样例

进入实际开发目录后，读取项目指南并识别已有 Dalamud 工程。记录客户端区域与完整 build、Dalamud API 与程序集、.NET 目标、FFXIVClientStructs、Penumbra API、Blender 和 glTF 导入导出器版本。

公开 SamplePlugin 使用 Dalamud.NET.Sdk，但公开模板的版本不能作为国服版本结论。通过目标安装与兼容模板确定 SDK，再锁定依赖。不要为沿用旧转换库引入另一份不匹配的 ClientStructs DLL。[SamplePlugin](https://github.com/goatcorp/SamplePlugin)，[Dalamud 开发入门](https://dalamud.dev/faq/getting-started/)

选择一个正常工作的上衣附加骨架样例，保存其 SKLB、MDL、EST、基础骨架、mapper 和解析路径。样例的种族和性别固定。无附加骨架的服装先使用已验证的 donor template 建立独立后续样例。

通过标准：工程可在目标 Dalamud 加载，显示版本和纯托管诊断；样例资源来源与加载关系已确定。

## M1 实现 SKLB 只读解析与 Havok 未编辑往返

完成包装布局与边界检查，提取 HKX 并得到纯托管快照。只在支持的国服适配器可用时调用客户端 Havok。先验证未编辑载入、保存，再将 HKX 放回包装。

实现对象图保留策略。VFXEditor 的骨骼写入代码可作为原生数组写入参考，但本项目必须保留模板中未编辑的 NamedVariants 和辅助对象，不只重建已知动画容器与 mapper。[SklbBones 写入参考](https://github.com/0ceal0t/Dalamud-VFXEditor/blob/05f6eb0cce19a6a91ae275bce609299d573914b3/VFXEditor/Formats/SklbFormat/Bones/SklbBones.cs)

通过标准：包装、骨架语义和辅助引用比较通过；输出可重新读取；以测试 Mod 替换后原服装外观与运动正常。若这里失败，先修复适配层，不继续扩展编辑功能。

## M2 实现 glTF 未编辑 Blender 往返

实现服装 skeleton 的 glTF 导出、代理 skin 与 sidecar。先按 VFXEditor 指南验证一个人工 Blender 往返，再把已验证参数固化进配套插件。选择一个实际 Blender 版本，不同时兼容大量版本。

实现原骨 UUID 对应、显示骨轴校正、对象变换检查和原索引保护。对不支持的缩放与复杂骨架明确禁用编辑。

通过标准：全部原骨保留，保护字段一致，坐标与姿态误差符合样例容差；未编辑结果在国服中表现一致。

## M3 验证单骨追加与服装权重闭环

在选定服装附加骨架追加一根唯一命名骨骼，挂到已被正确映射的原父骨。检查 layer、mapper、unmapped 骨处理、分区等是否需要更新，建立这套模板的明确策略。

用户在 Blender 将一个小测试 mesh 或服装小区域完全绑定到该骨，通过现有模型工具转回 MDL。本插件读取并核对新 MDL 的骨表和有效骨架组合。

生成包含 MDL、SKLB 与必要 EST 的测试部署。确认新 mesh 使用目标骨骼，随正确父骨运动，并能恢复原替换。

通过标准：新增骨骼参与真实服装蒙皮且往返稳定。若骨已存在但测试 mesh 不动，分别排查实际加载骨架、MDL 骨表、权重、mapper 和连接信息，不能仅反复调整坐标。

## M4 制作 Blender 配套插件与校验面板

配套插件提供导入项目、添加骨骼或简单骨骼链、检查身份与只读参考、导出回导版本。骨骼链模板只处理编辑便利性，不附带自动物理承诺。

面板提供来源选择、导出、回导、差异树、错误定位、候选版本和报告。用户可以保留多个候选，并看见哪些骨被服装实际加权。

通过标准：用户不需要手动选择一组易错的转换参数；一个原骨改名、循环或项目错配会在调用 writer 前被阻断。

## M5 集成 Penumbra 预览与正式 Mod 输出

实现 API 能力探测、当前目标路径解析、集合影响范围、临时替换和重绘。实现当前版本 metadata manipulations 的正确序列化；将 EST 变更纳入预览和正式输出。

临时集合单角色预览必须验证原服装有效设置保留。首版可先提供指定测试集合预览，明确提示共享作用范围，再完善单角色配置复制。

正式安装先输出独立 Mod 文件夹；现有 Mod 的 group 和 option 合并在独立步骤完成。保留原配置快照，检查外部变化，支持撤销。

通过标准：候选最终解析路径正确，停止预览恢复原服装，插件重载和 Penumbra 停用时处理本项目临时状态，输出 Mod 重新导入后仍正常。

## M6 扩展真实服装制作能力

单骨闭环通过后增加多骨链、多个加权 mesh、更多服装模板、头部装备附加骨架和已验证的其他种族。对跨种族方案增加参考骨架、mapper 与权重适配检查；不承诺只改 raceCode 就能复用。

物理摆动是独立后续项目，需要识别服装实际使用的动态资源、格式、骨引用、碰撞和运行逻辑。PAP 专用动画和姿态工具集成也独立立项，以实测为依据。

## 建议的工程结构

```text
src/
  ClothingSkeleton.Plugin/
  ClothingSkeleton.Core/
  ClothingSkeleton.Sklb/
  ClothingSkeleton.HavokRuntime/
  ClothingSkeleton.Exchange/
  ClothingSkeleton.ModelValidation/
  ClothingSkeleton.Penumbra/
blender/
  clothing_skeleton_bridge/
tests/
  Core/
  Exchange/
docs/
  planning/
```

纯托管 Core 和 Exchange 可以做独立自动测试。原生转换、Dalamud 加载与实际服装运动通过目标客户端中的集成样例验证。Blender 插件发布时包含兼容版本和安装说明。

## 主要风险与对应门槛

| 风险 | 应对与决定继续的依据 |
| --- | --- |
| 国服与上游布局或签名不同 | M0 锁定，M1 验证；失败时禁用原生写入 |
| 转换丢失 mapper、layer 或未知对象 | 基线对象图保留和重新解析；未支持引用阻断 |
| Blender 改变骨轴或丢失未加权骨 | sidecar 身份与明确 skin 列表；M2 未编辑比较 |
| 只追加骨骼但服装没有正确蒙皮 | M3 单骨加权测试；静态与运行报告分别记录 |
| 对所有服装部位错误套用 EST | 首版上衣；其他部位单独验证加载机制 |
| 共享 skeleton 路径影响其他装备 | 预览显示影响范围；正式安装检查冲突和关联 |
| 同期实现完整 MDL 转换造成范围膨胀 | 使用现有模型工具；本插件先实现关联检查 |
| 新骨未自动摆动被误认失败 | 明确第一版是父骨跟随与蒙皮；物理另设路线 |

## 开发阶段需要补充的具体数据

客户端完整 build 和目标 Dalamud 版本、用户实际 Blender 版本、首个服装部位和替换装备、种族性别、对应 SKLB 与 MDL、EST 与 mapper 样本、用户已有模型回导工具。

其中版本信息和资源路径由开发目录与目标环境读取；样例需要来自实际制作项目。当前不固定装备 ID、skeleton ID、国服 API 数字或 Havok 签名。
