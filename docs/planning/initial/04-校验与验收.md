# FFXIV 服装骨骼校验与验收

合法性必须分成可明确检查的层次。插件可以验证文件结构、引用和所选服装的依赖关系；实际运动表现需要在目标国服客户端验证。未经检查的依赖应显示“未验证”，不能显示为通过。

## 校验状态

| 状态 | 含义 |
| --- | --- |
| 阻断 | 已发现会破坏协议、文件或受保护结构的问题；禁止安装 |
| 警告 | 能生成文件，但存在明确效果限制或较广影响范围 |
| 未验证 | 缺少 MDL、模板规则或运行环境，无法判断相应条件 |
| 静态通过 | 在支持范围内完成文件与依赖检查 |
| 实测通过 | 当前版本候选已完成记录的游戏内验收场景 |

面板分别显示骨架结构、服装依赖、部署计划和运行实测状态。候选 SKLB 的哈希变化后，原实测记录自动失效。

## 校验规则

| 编号 | 检查内容 | 处理 |
| --- | --- | --- |
| F001 | SKLB magic、完整版本组合、最小长度和数据布局 | 未知或损坏版本阻断写入 |
| F002 | HavokOffset、data size、layer 范围、填充与所有读取边界 | 越界或整数溢出阻断 |
| F003 | HKX 能由匹配版本适配层读取；所选 skeleton 唯一明确 | 类型或骨架对象不明阻断 |
| F004 | bones、ParentIndices、ReferencePose 数量相符 | 不一致阻断 |
| B001 | parent 在同一输出 skeleton 内有效，根语义符合模板 | 跨参考骨错误引用或越界阻断 |
| B002 | 无自引用、循环；图遍历有边界 | 循环阻断 |
| B003 | 原骨 UUID、名称、索引、父关系与保护字段完整 | 第一版变更阻断 |
| B004 | 新骨 UUID 唯一，名称与原骨和有效组合骨架无冲突 | 重复或歧义阻断 |
| B005 | 骨骼名的字节编码和长度符合目标工具链 | 不能编码或超支持长度阻断；首版推荐简单 ASCII |
| B006 | 新骨稳定追加，所有新父引用已确定 | 输出不确定阻断 |
| B007 | 骨数及索引在各实际字段容量内 | 溢出阻断；不杜撰统一游戏骨数上限 |
| T001 | TRS 与矩阵所有数值有限 | NaN、Infinity 阻断 |
| T002 | 四元数非零且规范化程度可接受 | 零旋转阻断；允许的规范化需记录 |
| T003 | 新骨无零缩放、负缩放、未支持的非均匀缩放或 shear | 第一版阻断 |
| T004 | Armature 对象变换、单位和坐标配置一致 | 不一致先修正再回导 |
| T005 | 回导读取静止姿态；editorOnly 骨和参考骨未混入 | 未分离阻断 |
| H001 | wrapper 的 Bone Connect Index、Parents、layers 引用仍有效 | 有效性不明阻断部署 |
| H002 | 所有 mapper 的源目标 skeleton 正确，simple 和其它引用有效 | 越界、方向错误或源对象不符阻断 |
| H003 | LocalFrames、Partitions、float data 和额外 NamedVariants 保留 | 未支持的相关结构阻断编辑 |
| H004 | 模板对新 unmapped 骨和相关列表的处理规则明确 | 缺少规则标记未验证 |
| M001 | 已转换 MDL 的骨骼名均能在实际有效骨架组合中唯一解析 | 缺骨或歧义阻断整套部署 |
| M002 | MDL 各 mesh 骨骼表索引与权重引用有效 | 越界阻断 |
| M003 | 各 mesh 的骨骼表容量符合该 MDL 版本 | 超限阻断并定位 mesh |
| M004 | 权重有限、非负，和及影响数符合目标模型格式 | 错误阻断；不过度自动修复 |
| M005 | 新骨是否真的被服装使用；蒙皮静止矩阵是否匹配 | 未加权给效果警告；绑定姿态不符阻断部署 |
| D001 | EST 指向计划 skeleton，种族、装备标识和部位匹配 | 不一致阻断；缺失配置显示未完成 |
| D002 | MDL、SKLB 游戏路径正确且本地候选存在 | 路径错误或缺文件阻断 |
| D003 | 目标路径共享范围、冲突与最终解析结果 | 共享影响给警告；候选未生效阻断完成状态 |
| D004 | 国服客户端、适配器、Dalamud 与 IPC 能力吻合 | 不兼容时禁用原生写入或预览 |
| P001 | 源哈希、返回文件哈希、项目 UUID 和完成标记一致 | 混入其他版本阻断 |
| P002 | 安装或覆盖前原文件没有外部变化 | 冲突时重新生成部署计划 |

M001 不能只比对一份 SKLB，应同时考虑基础骨架、服装附加骨架与实际加载的相关资源。MDL 的骨骼表与 SKLB 全局索引是不同层次，不能直接把 Blender bone ordinal 写成模型骨骼表项。

模型容量参考：[Penumbra Model IO](https://github.com/xivdev/Penumbra/wiki/Model-IO#limitations)。包装和 Havok 辅助引用依据：[SKLB layer](https://github.com/0ceal0t/Dalamud-VFXEditor/blob/05f6eb0cce19a6a91ae275bce609299d573914b3/VFXEditor/Formats/SklbFormat/Layers/SklbLayer.cs)，[hkaSkeleton](https://github.com/aers/FFXIVClientStructs/blob/main/FFXIVClientStructs/Havok/Animation/Rig/hkaSkeleton.cs)。

## 检查器的输入和输出

输入为受信基线快照、返回骨骼图、已转换的 MDL 快照、目标 EST、路径部署计划及运行时能力。纯托管检查应在调用 Havok writer 前完成；生成后再验证可读取的候选文件。

每条报告包括 code、severity、对象身份、字段、实际值、期望或允许条件和用户可执行的修正方法。报告记录规则版本、候选哈希、依赖哈希及已检查范围。

若用户只回导骨架，没有提供重新转换的 MDL，允许保存骨架候选与报告，但整套服装依赖标记为未验证。不能在此状态给出“可安全安装整套 Mod”的结论。

## 需要准备的样本

真实样本在开发目录从用户的国服环境和服装项目取得，规划资料不提供或编造游戏二进制。

| 样本 | 验证目的 |
| --- | --- |
| 一个目标种族的基础骨架 | 参考空间、名称和附加骨架锚点 |
| 一套已正常工作的上衣附加 SKLB 与 MDL | 首个往返基线和 mapper 规则 |
| 同装备的原版 EST 与当前集合配置 | 路径和装备关联 |
| 目标种族的服装 Mod、材质和必要模型输入 | 权重和实际外观验证 |
| 追加一根骨、一个测试 mesh 的最小样例 | 跟随父骨的实际行为 |
| 追加三根骨的装饰件链 | 新父新子顺序、局部姿态和蒙皮 |
| 共享 skeleton ID 的另一件装备或角色 | 部署影响范围 |
| 已使用其他骨架或身体 Mod 的集合 | 冲突与基线选择 |
| 非单位缩放或复杂 mapper 的骨架 | 支持边界；不作为最初样例 |

## 自动验证与人工验收

以下为开发验收要求，当前规划阶段尚未运行。

| 用例 | 通过标准 |
| --- | --- |
| 未编辑 SKLB 经 Blender 往返 | 原骨名、索引、parent 和保护字段一致；静止姿态在声明容差内一致；辅助数据保留；游戏外观和运动不变 |
| 单骨追加 | 原索引不变，新骨追加且 parent 正确；候选可重新解析；测试 mesh 绑定它并随正确父骨运动 |
| 三骨链 | 局部姿态累积正确，没有轴向跳变；各新骨均被保留 |
| 未加权新增骨 | 文件可生成，报告明确提示缺少本次服装蒙皮效果 |
| 丢失或改名原骨 | 回导阶段即阻断，未调用原生 writer 或安装接口 |
| 循环、重复 UUID 或重复名称 | 报告准确定位问题；处理大图不无限递归 |
| 单位、对象变换或 roll 出错 | 显示具体差异，不能静默接受扭曲结果 |
| mapper 或 layer 索引损坏 | 候选进入部署之前阻断 |
| MDL 缺骨或 mesh 骨表超限 | 定位模型和 mesh，提示回到模型工具修正 |
| 目标装备没有正确 EST | 提示建立或修正配置；不称已实装 |
| 预览与回滚 | 只有展示的集合作用范围改变；停止后恢复原解析路径和外观 |
| 插件重载、取消转换或 Penumbra 停用 | 不遗留项目的临时替换；未完成候选不生效 |
| 国服版本不匹配 | 面板给出版本差异；原生能力禁用；纯文件规划可继续 |

未编辑往返的建议初始容差为：平移 1e-5 个游戏单位，旋转角 1e-4 弧度，缩放分量 1e-5。它们是待样本校准的工程目标，需同时观察最大局部和世界空间误差。不能据此保证所有复杂缩放骨架兼容。

Havok 重新序列化可能改变二进制布局，HKX 哈希不同不必然说明语义变化。对未修改的 wrapper 和不参与修改的字段，应比较原字节或规范快照；对骨架语义比较身份、引用、变换与辅助对象。两种比较不能互相替代。

游戏内第一轮覆盖站立、行走、转向、常用动作、装备切换和重绘。复杂服装后续再增加坐姿、骑乘、LOD 切换与其他场景；每次新增风险或能力才扩展测试。
