# FFXIV 服装骨骼插件开发交接

项目目的已经确定：为国服 FFXIV 的服装替换 Mod 添加自定义骨骼。用户希望通过 Dalamud 插件导出选中的 SKLB，在 Blender 编辑，再回导转换为 SKLB，在面板校验并通过路径替换安装。

## 已定技术方向

采用 Dalamud 插件与轻量 Blender 配套插件。主交换载体为 glTF 2.0，配套 JSON 保存来源、骨骼身份、原索引和游戏保护字段。原始 SKLB 为只读基线，候选通过国服匹配的客户端 Havok 适配层保存。

首版使用上衣附加骨架模板，保护原骨和基础骨架参考，只追加自定义骨。服装的 MDL 回导由用户已有模型工具完成；本插件检查骨骼表、权重与有效骨架组合，并关联必要的 EST 和 Penumbra 路径。

首个有效验收不是“生成了 SKLB”，而是“在真实服装中追加一根骨，绑定小测试 mesh，在国服客户端验证随父骨运动，且能回滚”。

## 开发目录中的启动任务

以下内容可直接作为进入实际工程后的任务说明。

> 为国服 FFXIV 开发服装自定义骨骼 Dalamud 插件。先阅读 docs/planning 中这套规划和工程内适用的项目指南，检查已有代码与开发环境，再从 M0 和 M1 开始实现。
>
> 首要用途是服装替换 Mod 的附加骨架编辑。先选一个上衣、一个种族性别、一套正常工作的服装附加 SKLB 与 MDL。读取实际 EST、基础骨架、mapper 和 Penumbra 解析路径，不编造装备或骨架 ID。
>
> 先做受控的 SKLB 与 Havok 未编辑往返，再做 glTF 与 Blender 未编辑往返，最后追加一根骨骼并完成服装蒙皮测试。所有旧骨保留身份、名称、索引和受保护关系；新骨追加。保留包装、layers、mapper、LocalFrames、Partitions、float data 和其他对象，遇到不支持的相关结构阻断编辑。
>
> 采用纯托管 Core 加独立 unsafe HavokRuntime 的结构。Havok 操作在 Framework 线程串行执行，后台仅处理托管快照与文件。使用从文件载入的私有对象图生成候选，不修改角色正在使用的 skeleton。
>
> glTF 加 sidecar 保留骨骼身份与坐标校正。轻量 Blender 插件封装参数，锁定基础参考骨，检测重复 UUID、丢失原骨、对象变换和不支持缩放。回导只读静止姿态。
>
> 第一版利用现有模型工具完成 MDL 转换；本插件验证结果并负责骨架转换、EST 部署计划、Penumbra 临时预览与独立 Mod 输出。没有验证的 MDL 或运行环境必须显示未验证。实现完成后按规划中的最小样例进行验收，并报告证据和仍未支持的结构。

## 要带入工程的资料

把本目录复制到实际项目的 docs/planning。sources.json 保留可复查的 upstream 提交与来源链接，代码移植时另行记录实际文件和许可证。

按实际环境取得并存放开发样本：服装 SKLB、基础参考骨架、MDL、EST 和必要相关资源；它们属于测试输入，不放进公共仓库或插件发行包。为自动测试构造最小托管图和错误样例即可，不需要随公开代码分发完整游戏文件。

## 当前阶段的完成边界

产品范围、格式取舍、转换参考、服装加载依赖、交换协议、校验规则、里程碑和开发交接均已整理。原生代码可行性来源于公开实现，尚未用用户的国服客户端、实际 SKLB 或 Blender 环境完成运行验证。

接下来进入实际开发目录时，先读取本地环境和样例，再将协议草案冻结为第一版实现。遇到国服适配、复杂 mapper 或动态资源差异时，根据具体证据调整支持范围。
