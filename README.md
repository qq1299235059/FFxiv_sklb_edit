# FFXIV 服装骨架工作台 0.7.0

为 FFXIV 国服服装替换 Mod 制作模型与自定义骨骼。在游戏选择自己或当前目标，把原版人物骨架和可选模型发送到已打开的 Blender；编辑后，一键返回对应的 Mod 项目。

0.7.0 按 Mod 管理文件，支持“仅骨骼”和“完整服装＋骨骼”。每件装备使用**独立集合、独立骨架、独立 glTF/MDL**，便于拆分上衣、下装、手套、鞋子等部件。没有新增服装骨骼时不生成 SKLB，并移除本工具上一版生成的旧骨架替换。

## 安装

在游戏输入 `/xlplugins`，打开**设置 → 实验性 → 自定义插件仓库**，添加并启用：

```text
https://raw.githubusercontent.com/qq1299235059/FFxiv_sklb_edit/main/repo.json
```

保存、刷新列表，搜索“服装骨架工作台”或“Clothing Skeleton”并安装。当前仓库直接提供开发预览版，无需打开测试版本开关。同一时间只启用一份游戏插件。

在 Blender **偏好设置 → 插件 → 从磁盘安装**中安装下面的配套 ZIP，并启用 **Clothing Skeleton Bridge**。更新后重新启用插件，必要时重启 Blender。**0.7 使用新的互通协议，游戏与 Blender 两侧必须一起更新。**

- [Dalamud 插件 ZIP](https://raw.githubusercontent.com/qq1299235059/FFxiv_sklb_edit/main/downloads/0.7.0/ClothingSkeleton-0.7.0.zip)
- [Blender 插件 ZIP](https://raw.githubusercontent.com/qq1299235059/FFxiv_sklb_edit/main/downloads/0.7.0/ClothingSkeleton-Blender-0.7.0.zip)
- [SHA256](downloads/0.7.0/SHA256SUMS.txt) · [验证记录](downloads/0.7.0/verification.json)

输入 `/csw` 查看指引。保持 Blender 打开，3D 视图按 **N → 服装骨架 → 连接游戏**。默认连接本机 `127.0.0.1:43867`，无需填写 Blender 程序地址、返回目录，也不新开工程。一次连接一个 Blender；端口冲突时在两侧改为相同的空闲端口。

## 制作流程

1. **选择角色与 Mod**：读取自己或当前目标，确认人物类型；创建独立 Mod，指定主要装备的游戏 MDL 路径。文件优先存到 Penumbra 的 Mod 目录；未启用 Penumbra 时存到插件的 `Mods` 目录。
2. **选择发送内容**：仅骨骼，或完整服装＋骨骼。参考模型可分别勾选“身体与头部”“穿着装备”“武器”，来自该角色当前加载的资源，以制作姿态显示。人物及其他参考骨架始终读取原版 SqPack，不使用人物 Mod 附带骨架。
3. **选择附加骨架**：使用当前上衣的原版附加骨架，或选择与人物匹配的上衣模板。只改模型且不加新骨时，可选“无附加骨骼”模式。然后创建并发送到 Blender。
4. **编辑对应部件**：服装部件按装备分集合，每个部件绑定自己的骨架。新增骨链用 Blender 原生 **Shift+A / E** 创建；先选新链根骨，Shift 最后选父骨，**Ctrl+P → 保持偏移**。可以挂到手腕等人物骨骼。
5. **加入自制服装**：用 Blender 常规导入功能导入服装；在面板选择“网格归属部件”，选中网格后点“将所选网格加入服装”，完成该部件的 UV、材质槽与权重。可逐个勾选本次发送的模型部件。
6. **返回与检查**：选择“仅骨骼”或“完整服装＋骨骼”，点击发送。游戏默认自动检查并更新该 Mod；也可关闭自动处理后手动检查。检查通过后在 Penumbra 选择需要的角色集合并启用，或保存为 PMP 安装包。

每个骨架内还有**人物骨骼 / 服装原骨 / 服装骨骼**三个骨骼集合。只编辑新增骨骼，保留原骨名称、父级及静止姿态。新骨误放进人物集合会报错；“整理新增服装骨骼”可一键修复集合归属，不改变父级和位置。

场景中的部件骨架始终独立。游戏中多个部件若共用同一个上衣附加骨架资源，导出阶段临时合并新增链，生成一份 SKLB；不会在 Blender 合并你的工作骨架。新骨重名或无法连接的父级会明确报错。

## 输出与限制

- 默认输出位于当前 Mod 的 `files/<部件标识>/`：`clothing.gltf`、游戏读取的 `clothing.mdl`，以及确有新骨时的 `skeleton.sklb`。内部往返文件固定保存在该 Mod 的 `.csw` 中，无需指定路径。
- 完整服装模式更新本次发送的模型部件；未发送的旧模型输出会退役。仅骨骼模式保留并重新检查已有模型。没有新骨时移除本工具管理的 SKLB、骨架路径替换和 EST，模型输出保留。
- 模型回传保留 UV、权重等数据，沿用对应目标装备的材质路径。**当前不转换自定义贴图或游戏材质**；Blender 参考模型使用无贴图材质。不同材质的网格会在转换时分别处理。
- 新骨需要受支持的 `top` 上衣附加骨架模板；“无附加骨骼”模式不允许新增骨骼，也不写回人物基础 SKLB。辅助部件的新链需挂到主要骨架中可连接的人物挂点或自定义骨。
- 当前格式最多支持 4 个实际人体连接，原模板已有连接计入；同一挂点上的多条链共用一个连接。原有 mapper 等复杂结构仍受兼容检查约束。
- 不自动制作权重、动画或物理。输出通过文件校验后，仍需在游戏检查权重、动作、穿模及原装备骨链行为。创建或更新 Mod 不会自动启用到角色。
- 模型导出使用当前加载资源，可能依赖已有 Mod 的材质与体型。分发自己的 Mod 前请确认所需依赖，并只分发有权分发的资源。PMP 导出只包含最终默认选项文件，不包含人物参考和内部工作资料。

## 常见问题

- **找不到插件**：使用原始 `repo.json` 地址，确认仓库启用、网络可访问 GitHub，并核对客户端和 Dalamud API。
- **连不上或收不到项目**：两侧一起更新至 0.7，确认端口一致；断开其他 Blender；结束编辑或模态操作并回到对象模式。
- **重发后没有覆盖修改**：同一项目和内容会保留场景编辑。要重做原始状态，请在游戏重新创建项目；请自行保存 `.blend`。
- **没有新增骨骼却没有 SKLB**：这是预期行为，模型可独立实装。确需新骨时先选装备附加骨架模板。
- **服装部件绑定错误**：检查网格归属、唯一的骨架修改器和权重，避免将手套网格绑定到上衣骨架。
- **旧项目无法使用新流程**：读取场景角色并创建 Mod 项目；旧版骨架项目保留在原位置，但不自动转成完整服装项目。

完整说明见 [使用指南](docs/分发使用指南.md)。升级前备份自己的 Mod 工作目录和 `.blend`。发行包不含设置、日志、游戏资源或开发机路径；不要压缩使用过的整个插件目录分发。

## 开发

`src/ClothingSkeleton.Core` 包含骨架、交换格式和 Mod 输出校验；`src/ClothingSkeleton.Plugin` 包含 Dalamud、模型适配和原生转换；`blender/clothing_skeleton_bridge` 为配套插件源码。`tests` 和 `tools` 包含核心检查、真实 Blender 回归及打包工具。

运行 `python tools/bootstrap_sdk.py`、`./tools/build.ps1 -Test`、`./tools/build.ps1 -Release`。构建需匹配的 Dalamud 开发程序集；开发文件指令默认关闭。模型导入导出的兼容设置参考 [Penumbra Model IO](https://github.com/xivdev/Penumbra/wiki/Model-IO)。
